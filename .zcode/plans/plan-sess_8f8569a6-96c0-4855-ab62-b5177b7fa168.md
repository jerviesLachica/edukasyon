# Fix Remaining SchedMate Bugs

## Context from code exploration
Reconciling the audit against the current code, most reported items are **already fixed** in source (previous `// Bug #N fix` commits) or were audit misreads: widget task deep-linking is fully wired (`TaskRow.clickable` → `openAppForTask(taskId)` → `MainActivity` → `PlannerScreen` selection), "1 decks" ternary is correct, school save-time validation exists, bio has no lowercase, countdown/streak/progress-bar/date-header formatting are all fine. The emulator was running a stale APK — a rebuild + reinstall fixes those. **Four real issues remain:**

## Fix 1 — Deck deletion with confirmation dialog (main fix)
The data layer supports deck deletion (`DeleteJeviDeckUseCase`, `JeviRepository.deleteDeck` with soft-delete + default-deck guard) but **no UI ever calls it** — decks can't be deleted at all, and my audit's "no confirmation" concern gets solved by adding the dialog from the start.
- `ui/viewmodel/JeviViewModels.kt` — `JeviDeckDetailViewModel`: inject `DeleteJeviDeckUseCase`, add `deleteDeck()` that sets a `deckDeleted` event flag in `JeviDeckDetailUiState`.
- `ui/screens/JeviScreens.kt` — `JeviDeckDetailScreen`: add a delete `IconButton` in the `TopAppBar` actions (hidden for the protected "General" default deck); tapping shows an `AlertDialog` styled like the existing task delete dialog (`PlannerScreen.kt:596`: title "Delete deck", body "Are you sure you want to delete \"X\"? This can't be undone.", error-colored "Delete" confirm + "Cancel"). On confirm → `viewModel.deleteDeck()`; `LaunchedEffect` on the `deckDeleted` flag → `onBack()`.

## Fix 2 — Unsync from Google Calendar confirmation
`OtherScreens.kt` (~line 697): the Unsync button immediately bulk-removes calendar events with no confirm. Add `showUnsyncConfirm` state; button opens an `AlertDialog` ("Remove all SchedMate events from your Google Calendar?") with destructive confirm running the existing permission-gated `viewModel.unsyncFromGoogleCalendar(context)`.

## Fix 3 — School field live validation feedback
`OtherScreens.kt` `ProfileEditSheet` (~line 1280): validation only fires on Save with a snackbar. Add `isError` + `supportingText` to the School `OutlinedTextField` when input is non-empty and (length < 2 or contains no letters): "School name must be at least 2 characters and contain a letter."

## Fix 4 — Due-time picker 12-hour consistency
`ui/components/DueDateTimePicker.kt` (~line 268): the due-time `rememberTimePickerState` omits `is24Hour`, so on 24h-locale devices the picker shows 24h while display/save always use 12h AM/PM (`formatTime12h`). Add `is24Hour = false` to match the reminder picker (which already has this with a `// Bug #14 fix` comment).
