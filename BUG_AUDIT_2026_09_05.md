## 🔴 CRITICAL

### Bug #1: Widget task tap launches Google Calendar instead of app
**Location:** Home screen → SchedMate 2×2 widget → tap task row
**Observed:** Opens Google Calendar instead of navigating to Planner
**Root cause:** `WidgetRoot` has `.clickable(openAction)` which targets the entire widget surface. When tapping a task row (which has no `.clickable` modifier), the event bubbles to the parent and fires `openAction` → `actionStartActivity(MainActivity, start_tab="planner")`. However, the system or launcher intercepts the deep link and routes through Google Calendar (possibly due to calendar event deep-link being registered globally).
**Impact:** Primary widget use case broken — users cannot tap a task in the widget to open it in the app.
**Fix approach:** 
1. Make `TaskRow` itself clickable with a separate action that passes `taskId` as an extra.
2. In `MainActivity.onCreate()`, check for `taskId` intent extra and deep-link to the task in Planner.
3. Ensure only `TaskRow` click targets the task, not the entire widget surface.

**Workaround for now:** Tap the widget header (which opens Planner cleanly); users must then find the task manually.

## 🟠 HIGH PRIORITY

### Bug #2: Countdown labels missing time units
**Location:** Today screen → "next class" countdown display
**Observed:** Shows "2, 0" or "30" instead of "2h 30m" or "30m"
**Root cause:** Likely in `DateUtils` or widget countdown formatter: `Duration.toComponents { h, m, s }` is concatenated with "," instead of "h " / "m ".
**Impact:** Users don't understand countdown granularity (minutes vs hours).
**Files to check:** `DateUtils.kt`, `WidgetDataProvider.kt` (countdown formatting)

### Bug #3: "1 decks" grammar  
**Location:** JEVI → Decks card
**Status:** ✅ FIXED in commit `845bfb1`
**Details:** Pluralization now uses conditional: `"${count} ${if (count == 1) "deck" else "decks"}"`

### Bug #4: Deck delete has no confirmation
**Location:** JEVI → Decks → delete button
**Observed:** Deck is removed immediately with no dialog.
**Impact:** User-generated content (flashcard decks) can be deleted by accident.
**Fix:** Show `AlertDialog` with "Are you sure?" before calling `viewModel.deleteDeck(deckId)`.

### Bug #5: Edit Profile "School" field accepts "1"
**Location:** Profile → Edit Profile → School input
**Observed:** Accepts 1-character or numeric-only strings like "1" or "99".
**Impact:** Invalid/nonsensical school names stored in user profile.
**Fix:** Add validation:
  - Minimum 2 characters
  - Must contain at least one letter
  - Trim whitespace
  - Show error toast if invalid

### Bug #6: Bio field downcases to "jevi" 
**Location:** Profile → Edit Profile → Bio
**Observed:** Capitalized input "Jevi" saved as "jevi".
**Root cause:** Unintended `.lowercase()` call on bio string (likely a copy-paste from search normalization).
**Impact:** User data is modified without consent.
**Fix:** Remove `.lowercase()` from bio field save path; preserve original case.

## 🟡 MEDIUM PRIORITY

### Bug #7: JEVI "0d Streak" missing space
**Location:** JEVI Today card → streak display
**Observed:** Renders as "0dStreak" instead of "0d Streak"
**Root cause:** String concatenation: `"${days}d$streakLabel"` needs space: `"${days}d $streakLabel"`
**Fix:** One-line string template fix.

### Bug #8: JEVI progress bar at 0 XP shows ~80% fill
**Location:** JEVI Today card → XP progress bar
**Observed:** Visual progress is much higher than underlying value (0 XP).
**Root cause:** Progress value passed as percentage (0-100) but bar expects ratio (0-1), OR bar has an internal animation that doesn't reset.
**Fix:** Verify progress parameter; ensure `progress = xp / maxXp` (0.0..1.0).

### Bug #9: "0 cards · 0 due" misaligned
**Location:** JEVI Decks header
**Observed:** Right-aligned text flush against edge, no padding.
**Fix:** Add `paddingEnd = 8.dp` to stats row.

### Bug #10: Widget header "Saturday Sep 5" inconsistent format
**Location:** SchedMate 2×2 widget
**Observed:** Day-month order mixed ("Saturday Sep 5" vs "Sat, Sep 5").
**Root cause:** Manual string formatting without locale-aware `DateTimeFormatter`.
**Fix:** Use `DateTimeFormatter.ofPattern("EEEE, MMM d", Locale.getDefault())`.

### Bug #11: Widget long-press shows no "re-configure"
**Location:** Widget → long-press menu
**Observed:** Launcher offers Resize/Remove/App Info but no way to re-open widget config (theme picker).
**Note:** This is a launcher limitation. App could expose a re-configure deep link from widget header.
**Not blocking for v1.2.6.**

### Bug #12: Profile header card has hidden click region
**Location:** Profile → orange header
**Observed:** `.clickable` modifier present but no affordance; tap does nothing visible.
**Fix:** Either remove `.clickable` or wire to Edit Profile.

### Bug #13: QuickActionCard corner radii inconsistent
**Location:** Profile → quick action buttons
**Observed:** Adjacent cards have different radii (16dp vs 12dp).
**Fix:** Verify `QuickActionCard` composable applies consistent `RoundedCornerShape(16.dp)`.

### Bug #14: Edit Task time picker ambiguity (12h/24h)
**Location:** Planner → task edit → time picker
**Observed:** Setting "13:00" silently rounds to "1:00 PM" or shows "13:00 PM".
**Root cause:** `HourFormat` inconsistency between picker and formatter.
**Fix:** Verify `HourFormat` passed consistently; test 24h → 12h conversion.

### Bug #15: Google Calendar "Unsync" double-confirmation
**Location:** Calendar → unsync item
**Observed:** Two sequential "Are you sure?" dialogs.
**Fix:** Consolidate to single confirmation dialog.

### Bug #16: Empty-state image `contentDescription = null` vs "empty state"
**Location:** JEVI / Planner empty states
**Observed:** Some have `null`, others leak "empty state" impl detail to screen readers.
**Fix:** Replace with localized strings like "No decks available" / "No tasks yet".
